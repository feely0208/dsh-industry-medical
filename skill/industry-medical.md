# 医疗行业专项体检（dsh-industry-medical）

**什么时候用**：给医院、诊所、互联网医疗、医疗信息化厂商的项目做上线前自查，或准备等保 / 医疗行业测评材料时。
用户会说：「病历要保存多少年」「处方保存期限够不够」「电子病历有没有操作留痕」「医疗设备网络安全制度有没有」
「新建项目网络安全预算够不够 5%」「外包合同有没有网络安全条款」「人脸识别能不能只做一种」「基因样本项目有没有伦理批件和知情同意」。

## 怎么用

```bash
<cli 路径> --root <项目目录>       # 检查一个项目
<cli 路径> --demo                  # 用内置样本看检出效果
<cli 路径> --list-rules            # 列出判据与出处
<cli 路径> --html medical.html     # 出 HTML 报告（测评前留档）
```

## 它查什么

8 条医疗行业判据，拆成 11 条规则（`file-pattern` 与 `files-lack` 语义相反，一条规则只能有一个 check）：

| 规则 | 查什么 |
|---|---|
| `MED-EMR-RETENTION-1` | 病历/EMR 保存期限低于门急诊 15 年（5475 天）或住院 30 年（10950 天） |
| `MED-EMR-RETENTION-2` | 有病历库表/配置，但全项目没有写明 15 年 / 30 年的保存期限声明 |
| `MED-EMR-AUDIT-TRAIL-1` | 病历库表/实体缺操作人、操作时间、version、trace_id 等留痕字段 |
| `MED-EMR-AUDIT-TRAIL-2` | 全项目没有独立操作日志表，也没有 Envers / JPA Auditing / MyBatis-Plus 自动填充等框架级审计 |
| `MED-PRESCRIPTION-RETENTION` | 处方保存期限低于 1 年法定下限（<365 天、<12 个月、<1 年） |
| `MED-DEVICE-CYBER-POLICY` | 有 DICOM/HL7/PACS/监护/输液泵，却没有覆盖采购、安装、运行、维护、报废 ≥4 环节的医疗设备网络安全制度 |
| `MED-CYBER-BUDGET-5PCT` | 新建项目的预算/立项/概算文档里，网络安全占比 <5% |
| `MED-VENDOR-CYBER-CLAUSE` | 外包/设备合同没有同时写「网络安全/数据安全义务」与「违约责任」 |
| `MED-FACE-FALLBACK` | 有人脸识别/活体检测，却没有密码、短信、人工核验等非人脸替代方式 |
| `MED-HGR-ETHICS-CONSENT-1` | 有基因/生物样本/遗传资源模块，却找不到伦理审查批件或审查记录 |
| `MED-HGR-ETHICS-CONSENT-2` | 有基因/生物样本/遗传资源模块，却找不到知情同意模板或签署记录 |

**所有规则都带 `when`**：项目里没有对应特征时进「不适用」，不会硬报。纯前端 / 纯软件项目跑出来是 0 命中 + 规则不适用，不是「全绿」。

## 怎么读结果

1. **先看「检查规则 N/M 条」**。M 小于 11 时，剩下的规则因为 `when` 不适用跳过了，报告会列出是哪几条 —— 不适用 ≠ 没问题。
2. **命中 ≠ 违规**。它是提示你去确认：
   - 保存期限类：先确认这个数值是不是病历/处方的留存期，而不是导出缓存、备份轮转、临时文件 TTL；
   - 留痕/审计类：如果用了框架审计或独立审计服务，把证据（注解、`_AUD` 表、审计系统说明）留在仓库里；
   - 制度/合同类：文档可能在 OA 或纸质档案，命中了先确认，别补一份假的；
   - 预算类：只对新建项目适用，纯运维/改造/升级的预算文档会被跳过。
3. **别把它当合规结论**。它只回答「仓库里有没有可查的证据」，不验证系统实际行为，也不保证通过测评。

## 不要做什么

- 不要因为它报「缺伦理批件」就伪造一份批件 —— 要真去走伦理审查
- 不要为了让它变绿而删除保存期限配置 —— 隐藏配置不等于合规
- 不要把它当唯一的医疗合规证据 —— 它只覆盖这 8 条，其它请配合通用插件与人工审查
